Phishing-Resistant-Auth-Prototype

Прототип фишинг-устойчивой аутентификации на базе WebCrypto API и расширения Manifest V3
Phishing-Resistant Authentication Prototype via WebCrypto API & Manifest V3 Extension
Code Repository ↗
JavaScript (Node.js) WebCrypto API Ed25519 / HKDF Manifest V3 Extension IndexedDB SQLite / PostgreSQL Docker
Проблема:

Классические факторы аутентификации (пароли, SMS-коды и TOTP RFC 6238) уязвимы к современным атакам Adversary-in-the-Middle (AiTM) с обратными прокси (Evilginx2, Tycoon 2FA), перехватывающими сессионные токены в реальном времени из-за отсутствия криптографической привязки к каналу и origin. Аппаратный WebAuthn/FIDO2 решает проблему, но требует физических токенов и усложняет аварийное восстановление доступа, а синхронизируемые Cloud Passkeys подвержены локальным атакам подмены интерфейса (prompt spoofing) и не гарантируют неотчуждаемость ключей по стандарту NIST SP 800-63B AAL3. Возникла задача разработать и верифицировать программную альтернативу, эмулирующую origin-binding WebAuthn в браузере с анализом границ безопасности.

Архитектура решения:

Система спроектирована на JavaScript с изоляцией доверенных и недоверенных контекстов исполнения:
• Клиентская часть (Chrome Extension Manifest V3): фоновый Service Worker выступает в роли доверенной вычислительной базы (TCB), генерирует мастер-ключи, выполняет иерархическую деривацию доменных ключей через HKDF (RFC 5869, HMAC-SHA-256) и формирует асимметричные цифровые подписи Ed25519 (RFC 8032) через WebCrypto API. Недоверенный Content Script в isolated world транслирует DOM-события страницы (domain-auth-request) через chrome.runtime API с обязательной проверкой sender.origin. Изолированный Popup UI предотвращает фоновые атаки криптографического оракула, требуя явного подтверждения пользователя. Доменные ключи хранятся в IndexedDB как неизвлекаемые объекты CryptoKey (extractable: false).
• Криптографический протокол Challenge-Response: подписывается каноническая структура M = c ∥ dnorm ∥ "auth" ∥ t, связывающая одноразовый 256-битный серверный челлендж, нормализованный origin домена и метку времени.
• Серверная часть (Node.js/Express): выдает челленджи со строгим TTL (60 с), верифицирует подпись Ed25519 и выдает JWT; персистентность профилей реализована с поддержкой SQLite (better-sqlite3) и PostgreSQL.

Результаты в ИБ и разработке:
  • Формализована модель угроз по методологиям STRIDE и Attack Trees (деревья атак), определены границы доверия WebCrypto в браузере;
  • 11 эмпирических сценариев тестирования подтвердили полную нейтрализацию перехвата учетных данных при AiTM-фишинге (отказ аутентификации на нелегитимном origin);
  • Гарантированная защита от replay-атак за счет одноразовых 256-битных челленджей (ошибка 409 Conflict при попытке повторного использования);
  • Нейтрализация подделки запросов через XSS благодаря валидации sender.origin на уровне изолированного Service Worker и обязательному подтверждению в Popup UI;
  • Отсутствие разделяемых секретов и паролей на сервере — хранятся исключительно открытые ключи и метаданные;
  • Модульная архитектура с временем валидации подписи менее 25 мс и поддержкой двух СУБД (SQLite / PostgreSQL).
Problem:

Traditional authentication factors (passwords, SMS codes, and TOTP RFC 6238) are fundamentally vulnerable to real-time Adversary-in-the-Middle (AiTM) reverse-proxy phishing (Evilginx2, Tycoon 2FA) due to the lack of origin-bound and channel-bound cryptographic ties. Hardware-backed WebAuthn/FIDO2 mitigates this but introduces deployment hurdles and complex recovery paths, while synced Cloud Passkeys remain exposed to local prompt spoofing/overlay attacks and fail NIST SP 800-63B AAL3 non-exportability. This project addressed the design, implementation, and security boundary analysis of a software-based authenticator emulating WebAuthn origin-binding via WebCrypto API.

Architecture:

Built in JavaScript with rigorous isolation between trusted and untrusted execution contexts:
• Client Architecture (Chrome Extension Manifest V3): The background Service Worker functions as an isolated Trusted Computing Base (TCB) executing in a separate thread without DOM access. It performs domain key derivation via HKDF (RFC 5869, HMAC-SHA-256) and asymmetric signing using Ed25519 (RFC 8032) via WebCrypto API. An untrusted Content Script in an isolated world acts as a transport bridge for DOM custom events (domain-auth-request) using chrome.runtime messaging with sender.origin verification. An isolated Popup UI prompts explicit user approval to thwart silent background cryptographic oracle attacks. Keys are stored in IndexedDB as non-extractable CryptoKey objects (extractable: false).
• Challenge-Response Protocol: Signs a canonical structure M = c ∥ dnorm ∥ "auth" ∥ t, binding a single-use 256-bit server challenge, normalized origin, and timestamp.
• Server Architecture (Node.js/Express): Issues time-bounded challenges (60s TTL), verifies Ed25519 signatures, and grants JWTs; supports dual-database persistence across SQLite (better-sqlite3) and PostgreSQL.

Security & Development Outcomes:
  • Conducted comprehensive threat modeling using STRIDE and Attack Trees to define WebCrypto security boundaries;
  • 11 empirical attack scenarios validated complete mitigation of AiTM reverse-proxy phishing (strict authentication rejection upon origin mismatch);
  • Robust replay attack protection via single-use 256-bit server-side challenges (resulting in 409 Conflict on replay);
  • XSS-induced challenge forgery neutralized via browser-enforced sender.origin checks in the isolated Service Worker and mandatory user confirmation;
  • Zero shared secrets or passwords stored on the server — only public keys and metadata are persisted;
  • High-performance backend with signature verification latency under 25ms and pluggable dual persistence (SQLite / PostgreSQL).

-ML-Web-malware-detection

Детектирование вредоносного веб-контента на основе машинного обучения (Хакатон)
Machine Learning Web Malware Detection (Hackathon Project)
Code Repository ↗
Python Scikit-learn XGBoost Pandas NumPy BeautifulSoup Flask / FastAPI Docker
Проблема:

Сигнатурные антивирусные базы и статические правила WAF часто пропускают вредоносные скрипты с обфускацией, динамической генерацией полезной нагрузки или использованием легитимных функций JavaScript (eval, DOM-манипуляции). В рамках хакатона требовалось создать прототип системы для быстрого автоматического выявления вредоносного кода в веб-трафике с высокой точностью.

Архитектура решения:

Конвейер обработки включает модуль извлечения признаков (энтропия строк, частотные n-граммы токенов, количество и глубина специфических вызовов JS API, структурные метрики DOM) и модуль инференса на основе ансамблевых моделей градиентного бустинга и случайных лесов. Решение оформлено в виде микросервиса, принимающего веб-страницы и JS-скрипты на вход и возвращающего оценку степени угрозы с интерпретацией ключевых индикаторов.

Результаты в ИБ и разработке:
  • Успешная разработка и валидация модели в условиях ограниченного времени хакатона;
  • Высокие показатели точности (Precision/Recall > 0.93) на тестовых наборах реального обфусцированного веб-вредоносного ПО;
  • Скорость оценки подозрительного скрипта менее 100 мс, что позволяет использовать сервис для предварительной фильтрации трафика;
  • Интерпретируемость детекта: сервис возвращает конкретные признаки и фрагменты кода, вызвавшие срабатывание.
Problem:

Traditional signature-based detection and static WAF rules often fail against obfuscated web malware, polymorphic malicious JavaScript, and zero-day payload injection. Developed as a fast-paced hackathon project, the challenge was to design and train an automated machine learning system capable of detecting malicious web content with high accuracy and low false-positive rates.

Architecture:

The processing pipeline features an automated feature extractor (Shannon string entropy, lexical token n-grams, suspicious JavaScript API call frequency, and structural HTML/DOM properties) coupled with an ensemble gradient boosting classifier (XGBoost/RandomForest). The inference engine is packaged into a lightweight REST microservice that evaluates incoming payloads and returns confidence scores alongside indicator breakdowns.

Security & Development Outcomes:
  • Successfully built, trained, and benchmarked within strict hackathon deadlines;
  • Achieved strong classification benchmarks (Precision and Recall exceeding 0.93 on real-world obfuscated malware datasets);
  • Sub-100ms inference time per payload, making it suitable for edge gateway filtering;
  • Transparent risk reporting with granular feature contribution breakdowns for security analysts.

Monitoring-Bot

Бот оперативного мониторинга серверов безопасности
Operational Infrastructure Security Monitoring Bot
Code Repository ↗
Python aiogram / asyncio Linux system APIs (psutil, systemd) Docker SQLite
Проблема:

Администраторам безопасности и инженерам инфраструктуры необходим быстрый канал получения критических уведомлений о сбоях в работе серверов и защитных служб без необходимости постоянного открытия тяжелых веб-дашбордов или прямого SSH-доступа с мобильных устройств.

Архитектура решения:

Асинхронный Telegram-бот, взаимодействующий с локальными демонами и системными интерфейсами Linux. Сервис отслеживает нагрузку на вычислительные ресурсы (CPU, RAM, состояние дисковых накопителей), статус критических демонов (systemd services), доступность сетевых портов и целостность правил брандмауэра. Реализована строгая модель контроля доступа (авторизация по белому списку Telegram ID), шифрование локальных данных и санитаризация команд для предотвращения инъекций.

Результаты в ИБ и разработке:
  • Мгновенное оповещение дежурного специалиста (задержка доставки алерта < 2 секунд);
  • Безопасный интерфейс для выполнения регламентных операций (перезапуск упавших служб, сбор свежих логов инцидентов) без открытия прямого SSH-доступа во внешнюю сеть;
  • Минимальное потребление ресурсов на хосте (< 40 МБ RAM), отсутствие влияния на целевые процессы безопасности;
  • Стабильная непрерывная работа в изолированном Docker-контейнере.
Problem:

Security administrators and systems engineers require instant, reliable alert delivery and health status checks for critical servers and security services without relying on heavy web dashboards or opening direct remote SSH sessions from untrusted networks.

Architecture:

An asynchronous Telegram bot integrated directly with Linux system diagnostics and process managers. The service continuously monitors host resource consumption (CPU, memory, disk thresholds), systemd daemon states, security service uptimes, and firewall status. It incorporates strict security controls: hardcoded administrator whitelist verification (RBAC), sanitized command execution parsers to eliminate injection risks, and encrypted configuration storage.

Security & Development Outcomes:
  • Near-instantaneous incident alerting (notification delivery latency under 2 seconds upon threshold breach);
  • Secure diagnostic interface for executing routine health tasks and retrieving log snippets without external SSH exposure;
  • Low resource footprint (< 40 MB RAM), ensuring zero performance penalty on monitored security infrastructure;
  • Containerized deployment with automated recovery and health check probes.
